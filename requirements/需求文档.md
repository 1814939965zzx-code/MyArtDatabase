# artDatabase 需求文档

> 汇总文档：整合项目现状事实、现阶段需求与更新需求记录。
> 最后更新：2026-08-16
> 本文档是需求的唯一总入口；`requirements/` 下按「日期 + 版本」命名的文件保留为历史存档。

## 一、项目现状事实

### 1.1 已完成功能

核心功能已实现并可本地运行：

- **项目管理**：创建、重命名、删除、复制项目。
- **项目维度**：创建/删除维度，维度值通过 Slider 连续编辑（`0.00～10.00`，保留两位小数）。
- **图片上传**：文件选择、拖拽、剪贴板粘贴；JPEG/PNG/WebP 单图上传，单文件上限 50MB；上传前 SHA-256 完全重复检测，可引用已有素材或保留为新素材。
- **素材浏览与筛选**：统一尺寸网格 + 列表切换，按名称/文件名/标签搜索，标签多选 OR 筛选。
- **维度预览**：一维轴 / 二维平面 / 三维空间自动对比，单次预览最多选择 3 个项目维度。
- **自由画板**：一个项目多张画板，创建/切换/重命名/删除；元素拖动、缩放、旋转、置顶/置底/移除；布局持久化，多人短轮询同步（不同元素互不覆盖，同一元素最后写入）。
- **Metadata 编辑**：名称、全局标签、描述、备注、来源链接；全局修改即时同步到所有引用项目。

### 1.2 当前技术架构

| 层 | 现状 |
| --- | --- |
| 应用运行时 | Cloudflare Worker（vinext + wrangler） |
| 结构化业务数据 | D1（SQLite），Drizzle ORM 迁移 |
| 图片二进制与缩略图 | ResourceSpace（HTTP API 读写） |
| Metadata | D1 `assets` 表 + ResourceSpace 双写（ResourceSpace 侧为冗余） |
| 前端 | React 19 + Vite（RSC）+ Tailwind |

数据表：`projects`、`project_dimensions`、`assets`、`project_assets`、`asset_dimension_values`、`canvases`、`canvas_items`。维度值以整数 `0～1000` 存储，对应 `0.00～10.00`，避免浮点精度问题。

### 1.3 需求状态概览

- 需求基线 v0.1 已完成，并被 v0.4 及 v0.6～v0.14 部分修订，v0.4 至今保持「当前有效」。
- v0.15「后端图片存储去 ResourceSpace 重构」处于**需求澄清中，尚未实施**：当前 ResourceSpace 仍承担原图与缩略图存储。

## 二、现阶段需求

### 2.1 项目目标与 MVP 范围

面向团队的图片素材库：素材文件与项目相互独立，项目通过引用组织素材；全局标签用于检索筛选，项目维度用于项目内排序与对比；自由画板是 MVP 核心功能。

- 首版只支持图片；视频、音频留作后续扩展。
- 本地部署，通过局域网提供服务。
- 不做用户注册、登录与权限；不支持批量上传；暂不要求备份。

### 2.2 核心概念

- **全局素材库**：团队共用，每个素材一条主记录、一份唯一 Metadata，素材不属于任何单一项目。
- **项目**：一级分类，通过引用（不复制文件）组织素材；同一素材可加入多个项目；Metadata 修改后所有引用项目同步。
- **Metadata**：与素材一一对应，字段见下表。
- **标签**：两个作用域——素材自身标签（全局，自由输入）与项目维度（项目级，左右端点 + 连续数值）。

MVP Metadata 字段：

| 字段 | 来源 | 可空 | 说明 |
| --- | --- | --- | --- |
| 素材名称 | 用户编辑 | 是 | 未填时用原始文件名展示 |
| 素材标签 | 用户编辑 | 是 | 全局自由输入 |
| 描述 | 用户编辑 | 是 | 对素材内容的描述 |
| 备注 | 用户编辑 | 是 | 团队内部补充信息 |
| 来源链接 | 用户编辑 | 是 | 素材原始来源 URL |
| 上传时间 / 原始文件名 / 文件大小 / 图片尺寸 / 文件格式 | 系统生成 | 否 | 自动记录 |
| 时长 | 系统生成 | 是 | 图片素材为空，为视频和音频预留 |

### 2.3 核心功能

- **素材浏览**：查看全局素材库与项目素材；按全局标签筛选（多选 OR）；按项目维度筛选。
- **项目页面**：默认展示项目全部素材，统一尺寸网格、居中裁剪缩略图、Hover 放大预览。
- **上传**：见 1.1；正式提交前弹出 Metadata 编辑窗口（全局标签 + 当前项目全部维度 Slider）；新素材自动加入当前项目并为全部维度创建赋值（默认 `5.00`）；取消则不创建记录、不提交上传。
- **移除与删除**：区分「从项目移除」（仅删引用）与「全局删除」（进回收站：查看/恢复/彻底删除）。
- **自动对比**：按所选维度数量使用一维轴 / 二维平面 / 三维空间排列，调整 Slider 后位置同步更新。
- **自由画板**：多画板、持久化布局、局域网多人共同编辑与同步。
- **项目管理**：创建/重命名/删除/复制；删除项目不删全局素材；复制项目时复制维度配置（是否复制素材引用与画板待确认）。

### 2.4 维度规则（v0.4 澄清后）

- 一个项目可创建**任意数量**维度，无「3 个」的项目级上限。
- 「最多 3 个」指单次维度预览最多选择 3 个项目维度作为坐标轴（1 → 一维轴，2 → 二维平面，3 → 三维空间）。
- 上传与编辑素材时显示并保存当前项目的全部维度值，不受预览选择上限影响。
- 维度值范围 `0.00～10.00`，保留两位小数，Slider 连续调整。
- 素材加入项目或项目新增维度时，对应维度值默认中点 `5.00`。
- 数据库以 `(projectId, assetId, dimensionId)` 唯一约束同一素材在同一项目同一维度下只有一个值。

### 2.5 三维预览交互规则（v0.6～v0.14 合并）

- 三轴从中心向正负两端放射、在中心相交；不显示承载平面或边框；轴两端显示维度左右端名称。
- 所有图片始终面向摄像机，不随旋转倾斜。
- 中键拖动改变视角；左键拖动图片改变前两个维度值；`Shift` + 左键拖动改变第三（深度）维度值；松开后写入服务端。
- 水平旋转完整 `360°` 循环，方向与鼠标移动一致；俯仰角范围 `0°～180°`，到两端停止、不循环。
- XY 平面为透明正方形网格，按 `0～10` 每 `1` 单位一格；网格平面仅作视觉参照、不参与鼠标命中，图片单独接收指针事件。
- 拖动图片按当前视角反投影，并保留按下点与图片中心的偏移，起步不跳变。
- 维度预览最小高度 `640px`，滚轮缩放 `35%～280%`；左侧菜单可隐藏；支持页面内「专注模式」（不调用浏览器 Fullscreen）。

### 2.6 后端图片存储重构方向（v0.15，需求澄清中）

- 目标：用**原生 Node.js 图片存储服务**（唯一依赖 `sharp`）承担原图与缩略图的写入/读取/删除，图片落本地磁盘卷；**完全移除 ResourceSpace** 依赖。
- 缩略图改为服务端生成（最长边 ≤ 900px 的 WebP），客户端不再生成。
- `/api/media` URL 契约不变，前端原则上无需改动；存储服务以 Bearer Token 鉴权，令牌只存服务端。
- D1 字段语义：`storage_key`/`thumbnail_key` 指向存储服务 blob id；`external_id` 弃用，仅用于存量迁移读取；`thumbnail_url` 保留用于外链回退。
- 软删/恢复不触碰文件，仅「彻底删除」触发存储服务删除；文件级去重仍由 D1 的 SHA-256 检查承担。
- 待澄清：存量 RS 素材迁移 vs 丢弃重置、Worker 与存储服务连通方式、客户端缩略图生成是否保留、单文件上限/缩略图尺寸、回收站 UI。

### 2.7 当前明确不做

- 不做图片裁剪、调色、加字等在线编辑；不做 Metadata 历史版本。
- 不复制素材文件到各项目；不支持视频与音频；不支持批量上传。
- 不提供用户账号、登录与权限分级；不提供自动备份。

### 2.8 待确认问题（合并自 v0.1 与 v0.15）

1. 图片在对比视图中重叠时，采用堆叠、自动避让还是聚合展示？
2. 标签筛选与维度视图能否同时使用？
3. Hover 放大预览采用原位放大、浮层还是放大镜？
4. 完全重复检测用文件哈希是否满足需求？提醒时是否允许直接引用已有素材？
5. 多人同时移动同一画布元素采用最后写入还是锁定？是否需要画布评论/文字/连线/导出？
6. 是否允许团队自定义 Metadata 字段？
7. 复制项目时是否复制素材引用与自由画布？
8. 未来 NAS 部署形态、支持的图片格式与单文件大小上限？
9. 存储重构：存量 RS 素材迁移策略、连通方式、客户端缩略图去留、回收站 UI（见 2.6）。

### 2.9 部署与云端注意事项

本地 / 局域网：

- 应用运行在 Cloudflare Worker 开发服务器，结构化数据在本地 D1；图片存储服务以独立进程监听本机端口（默认 `18082`），数据目录为本地卷。
- 存储路径与服务地址不硬编码，均通过环境变量配置，便于未来迁移到 NAS 或内部服务器。

云端部署（去 ResourceSpace 后，随 v0.15 落地）：

- 存储服务打包为单容器（`node:22-alpine`，唯一依赖 `sharp`），可部署到 Fly.io / Railway / Render / 任意 VPS。
- **必须挂载持久化卷**：图片文件落本地磁盘，重启后依靠持久化卷保留；未挂载卷会导致重启后丢图。
- **鉴权与连通**：存储服务须能被 Worker 访问（公网 HTTPS + Bearer Token，或 Cloudflare Tunnel / 私有网络）；`IMAGE_STORE_TOKEN` 经环境变量注入，不写入代码与镜像、不发往浏览器，Worker 仅在服务端持有令牌。
- Worker 侧仅需配置 `IMAGE_STORE_BASE_URL` 与 `IMAGE_STORE_TOKEN` 即完成接入；D1 由 Cloudflare 托管。
- 存储服务为单实例、单卷，MVP 不做分布式多实例共享存储。
- 配置项：`IMAGE_STORE_ROOT`（数据目录，默认 `<CWD>/data`）、`IMAGE_STORE_TOKEN`（必填）、`IMAGE_STORE_PORT`（默认 `18082`）、`IMAGE_STORE_THUMB_MAX`（缩略图最长边，默认 `900`）、`IMAGE_STORE_BASE_URL`（Worker 侧存储服务地址）。
- 资源与成本：单文件上限 50MB、缩略图最长边 900px，直接影响存储与带宽用量；MVP 暂不要求自动备份，云端建议为持久化卷另行配置备份。
