## 当前实现与问题

- orderLikedFirst 只稳定分组布尔 liked，没有记录 Like 之间的优先级或标记时间。
- 2D 基础顺序按 y 分行再按行内 x 排列，列数取决于堆成员数；缩放或切换维度使堆拆分、合并时，同为 Like 的图片可能改变相对顺序。
- 3D 收起封面基于 Page 素材顺序，展开平面在打开瞬间按深度排序；两处分别执行 Like 优先，所以同一堆有多个 Like 时，收起封面与展开第一张可能不同。
- Like 点击后立即重排展开卡片，操作按钮也随之移动。推测会增加误点或感觉标记错位的概率；本次未对用户反馈的全部切换场景做浏览器复现，不能把所有现象都归因于这一项。
- 上一轮测试覆盖了布尔分组稳定、保存与刷新，但没有覆盖“多个 Like 在重组前后及收起/展开的代表图片一致”这一产品规则。

## 相似产品的官方做法

1. Google Photos：每个照片堆有 Top pick，系统自动选择，但用户可以通过 Set as top pick 修改。官方明确说明 Top picks 不同于 favorite photos。
   https://support.google.com/photos/answer/14169846?hl=en
2. Lightroom Classic：堆以顶图代表收起状态；用户可以 Move To Top Of Stack，也可上下调整堆内顺序。评分和旗标是另外的属性操作。
   https://helpx.adobe.com/lightroom-classic/desktop/organize-photos-in-lightroom-classic/grouping-photos-stacks.html
   https://helpx.adobe.com/lightroom-classic/desktop/organize-photos-in-lightroom-classic/flag-label-rate-photos.html
3. Apple Photos：相簿可以选择或更新 key photo；相簿排序是另外的功能。这是相簿封面而非动态空间聚堆，不应直接照搬其数据模型。
   https://support.apple.com/guide/iphone/create-and-work-with-photo-albums-iphc0fc668ab/27/ios/27

以上是具体产品事实，不代表所有产品都采用相同规则。

## 推荐方案：Like 与封面分工

- Like 允许多个，表示希望优先看到；同为 Like 时使用稳定 Page 顺序或显式持久化的优先级，最后以素材 ID 打破平局。收起与展开必须使用同一代表图片判定。
- 增加“设为封面”操作，明确选择该堆的代表图片；Like 不再隐式等同于唯一封面。
- 本项目的堆会随缩放动态重组，不能只按临时 stack key 保存封面。建议在 Page-素材上记录用户指定封面的递增优先级；在当前堆成员中选择最高优先级。合并两个已有封面的堆时，最近明确指定的封面优先；拆开后优先级随素材保留。
- 封面选择顺序：成员中的明确封面优先级 → Like → 稳定 Page 顺序 → 素材 ID。固定、移除、删除的素材不参与当前堆代表选择。
- 展开时把当前封面放第一位，其余 Like 随后；当前一次 hover 中点击 Like 只更新心形，不立即移动鼠标下的卡片，下次展开或收起时重排。
- 堆显示 Like 数量，如“♥ 2”，避免用户误以为只有当前封面带有 Like。
- 不引入完整星级评分或任意拖拽排序，先控制交互复杂度。

## 更轻的替代方案

若不增加封面入口：保留单一 Like，记录首次 Like 的持久化顺序；最早 Like 优先，其他 Like 随后。取消后重加排到 Like 组末尾。它能消除不确定性，但用户指定封面需要取消其他 Like，操作意图较弱。也可以采用最近 Like 优先，但那意味着每点一次 Like 都会改变封面，需要明确告知。

## 后续验收

- 两个或更多 Like，在收起、展开、旋转、切轴、拆堆合堆、刷新和跨设备后，代表选择遵守同一规则。
- 显式封面的合并冲突、拆分回退、取消、移除与软删除均有可解释结果。
- 当前 hover 中按钮不因排序跳到别的素材，保存失败和连续操作不误回滚。
