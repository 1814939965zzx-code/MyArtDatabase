## 1. 项目目标

建设一个面向团队的图片素材库。MVP 首版只支持图片，未来可以扩展到视频和音频。素材文件与项目相互独立，每个项目通过引用的方式组织所需素材。素材自身标签用于全局检索和筛选，项目独有的维度信息用于项目内部的排序和对比。自由画布属于 MVP 核心功能。

### 1.1 MVP 范围

- 首版只支持图片素材。
- 视频和音频留作后续扩展，不进入首版验收范围。
- 自由画布属于首版核心功能。
- 首版部署在本地设备，并通过局域网提供服务。
- 首版不做用户注册、登录和账号权限系统。
- 首版不支持批量上传。
- 首版暂不要求备份能力。

## 2. 核心概念

### 2.1 全局素材库

- 所有团队成员共用一个全局素材库。
- MVP 存放团队的全部图片；数据结构预留未来支持视频和音频的可能性。
- 每个素材在系统中只保留一份主记录。
- 每个素材拥有唯一的 Metadata。
- 素材本身不属于任何单一项目。

### 2.2 项目

- 项目是一级分类，也是围绕一组素材开展工作的空间。
- 项目通过引用关系从全局素材库添加素材，不复制原始文件。
- 同一素材可以同时加入多个项目。
- 修改素材 Metadata 后，所有引用该素材的项目同步显示最新内容。
- 进入项目后，默认展示项目内的全部素材。
- 用户可以使用与项目相关的标签进一步筛选素材。

### 2.3 Metadata

- Metadata 与素材一一对应。
- 素材 Metadata 至少包含素材自身标签。
- 素材自身标签属于全局信息，与项目无关。
- 修改素材自身标签后，所有引用该素材的项目同步显示最新内容。
- 用户可以修改 Metadata；MVP 不要求在线编辑图片文件本身。
- Metadata 修改不需要历史版本。
- Metadata 允许部分字段为空。

MVP Metadata 字段：

| 字段 | 来源 | 是否可为空 | 说明 |
| --- | --- | --- | --- |
| 素材名称 | 用户编辑 | 是 | 未填写时可暂用原始文件名展示 |
| 素材标签 | 用户编辑 | 是 | 全局自由输入标签 |
| 描述 | 用户编辑 | 是 | 对素材内容的描述 |
| 备注 | 用户编辑 | 是 | 团队内部补充信息 |
| 来源链接 | 用户编辑 | 是 | 素材原始来源 URL |
| 上传时间 | 系统生成 | 否 | 素材首次创建时自动记录 |
| 原始文件名 | 系统生成 | 否 | 上传文件的原始名称 |
| 文件大小 | 系统生成 | 否 | 原始文件的字节大小 |
| 图片尺寸 | 系统生成 | 否 | 图片宽度与高度 |
| 文件格式 | 系统生成 | 否 | 例如 JPEG、PNG、WebP |
| 时长 | 系统生成 | 是 | MVP 图片素材为空，为未来视频和音频预留 |

### 2.4 标签

标签系统分为两个作用域：

1. **素材自身标签（全局）**：记录素材本身的属性，用于全局或项目内的分类和筛选，例如“人物”“户外”“暖色”。这些标签跟随素材，在所有项目中保持一致。团队成员可以自由输入标签，不强制从预设标签库中选择。
2. **项目维度（项目级）**：由项目创建，只在当前项目内有效，不在不同项目之间通用。每个维度包含左端名称和右端名称，例如左端“抽象”、右端“具象”，界面可将其组合显示为“抽象—具象”。项目维度用于表达素材在两个端点之间的连续位置。

项目维度定义与素材维度赋值是两个不同的数据对象。

项目维度定义：

```json
{
  "id": "dimension-001",
  "projectId": "project-a",
  "leftLabel": "抽象",
  "rightLabel": "具象",
  "min": 0,
  "max": 10,
  "decimalPlaces": 2
}
```

素材在项目维度上的赋值：

```json
{
  "projectId": "project-a",
  "assetId": "asset-001",
  "dimensionId": "dimension-001",
  "value": 1.25
}
```

同一素材在一个项目中包含多个维度值时，可以在接口层表示为：

```json
{
  "projectId": "project-a",
  "assetId": "asset-001",
  "dimensionValues": [
    {
      "dimensionId": "dimension-a",
      "value": 1.25
    },
    {
      "dimensionId": "dimension-b",
      "value": 7.8
    },
    {
      "dimensionId": "dimension-c",
      "value": 5.0
    }
  ]
}
```

- `ProjectDimension` 定义维度本身，供当前项目内的所有素材共用。
- `AssetDimensionValue` 记录某个素材在某个项目维度上的位置。
- `value` 不属于维度定义；它属于“素材与维度之间的赋值关系”。
- 一个维度只有一份定义，但可以对应很多条素材赋值记录。
- 同一个素材可以在同一项目中拥有多个维度值，每个项目维度对应一个独立的 `value`。
- 数据库以 `(projectId, assetId, dimensionId)` 作为维度赋值的唯一组合，确保同一素材在同一项目的同一维度下只有一个值。

同一个素材在不同项目中可以被赋予不同的维度值，互不影响。项目维度不使用固定档位，范围暂定为 `0.00～10.00`，数值保留两位小数。

- 一个项目可以创建多个维度，例如同时创建“抽象—具象”和“冷静—热烈”。
- 每个项目最多可以创建 `3` 个维度。
- 每个维度彼此独立。
- 同一个素材在同一项目的同一维度下只能拥有一个数值。
- 素材加入项目后，在该项目已有的每个维度上自动赋值为中点 `5.00`。
- 项目新增维度时，项目内已有素材在该维度上的初始值暂按 `5.00` 处理。

## 3. 核心功能

### 3.1 素材浏览

- 查看全局素材库中的全部素材。
- MVP 浏览和展示图片素材。
- 进入项目后查看项目引用的全部素材。
- 根据素材自身标签筛选素材。
- 根据当前项目创建的维度和值筛选素材。
- 前端一级入口以项目为主。

### 3.2 项目页面

进入项目后，项目页面默认加载并展示该项目引用的全部图片。项目页面包含默认素材视图和筛选、对比入口。

#### 默认素材视图

- 默认展示项目包含的全部图片。
- 在用户选择标签或维度展示方式前，不主动隐藏项目素材。
- 默认采用统一尺寸的网格布局。
- 每个素材使用固定大小的图片卡片展示。
- 网格根据页面可用宽度自适应每行卡片数量。
- 缩略图采用居中裁剪并填满卡片，不显示留白。
- 裁剪仅影响网格缩略图的展示，不修改服务器上的原始图片。
- 所有图片卡片保持统一展示尺寸。
- 鼠标 Hover 图片时显示放大预览，便于查看图片细节。

#### 标签筛选

- 系统汇总项目内素材拥有的全局素材标签。
- 用户选择某个标签后，筛选并展示项目内所有具有同名标签的素材。
- 用户可以同时选择多个标签。
- 多标签之间采用 OR 逻辑：素材只要包含任意一个已选标签，即进入筛选结果。
- 标签筛选仅改变当前项目的展示结果，不修改素材 Metadata。

#### 维度展示

- 用户可以在项目内添加维度。
- 每个项目最多添加 `3` 个维度。
- 素材依据其项目维度值排列到对应坐标轴上。
- 使用 `1` 个维度时，素材沿一条轴排列。
- 使用 `2` 个维度时，素材按照两个维度值排列在二维平面中。
- 使用 `3` 个维度时，素材按照三个维度值排列在三维空间中。
- 用户可以通过维度视图比较素材在不同方向上的相对位置。
- 三维空间支持旋转、缩放和平移。
- 用户可以在三维空间中放大查看单张图片。

### 3.3 素材添加与上传

- MVP 支持上传图片到全局素材库。
- 从全局素材库选择已有素材并添加到任意项目。
- 同一素材可以被多个项目引用。
- 暂不支持批量上传；每次上传一张图片并完成其 Metadata 编辑。
- 系统对上传文件进行完全重复检测。
- 发现完全相同的素材时，上传前提示用户该素材已经存在。
- 用户收到提示后仍可选择继续上传，从而保留重复素材记录。

项目页面至少支持以下图片输入方式：

- 将本地图片拖拽到项目页面。
- 从系统剪贴板粘贴图片。
- 通过本地文件选择器选择并上传图片。

项目内上传新图片的流程：

1. 用户通过拖拽、粘贴或本地文件选择器提供图片。
2. 系统在正式提交上传前弹出 Metadata 编辑窗口。
3. 编辑窗口展示素材自身的全局标签输入区域。
4. 编辑窗口自动列出当前项目的全部维度，并为每个维度提供 Slider。
5. 系统自动为新图片创建当前项目全部维度的赋值记录。
6. 每个项目维度的初始值默认为 `5.00`，用户可以在上传前调整。
7. 全局素材标签不自动生成，由用户在 Metadata 编辑窗口中手动添加。
8. 用户可以自由输入一个或多个素材自身标签。
9. 用户确认提交后，图片上传到服务器，创建全局素材记录，并自动加入当前项目。
10. 系统生成用于列表和空间视图展示的缩略图。
11. 系统提取文件大小、图片尺寸和格式等自动 Metadata。
12. 用户取消时，不创建素材记录，也不提交上传。

### 3.4 Metadata 编辑

- 查看单个素材的 Metadata。
- 编辑素材自身标签及其他全局 Metadata 字段。
- 全局素材标签允许自由输入；首版不提供已有标签的自动提示或补全。
- 修改全局 Metadata 后，所有引用该素材的项目立即显示最新内容。
- 在项目内为素材设置或修改项目维度值；该修改只影响当前项目。
- 项目维度值通过范围为 `0.00～10.00` 的 Slider 控件修改。
- Slider 支持连续调整，数值保留两位小数，不限制为固定档位。
- Slider 左右两端分别显示维度的左端名称和右端名称。
- 暂不保留 Metadata 历史版本。

### 3.5 从项目移除与删除

系统需要明确提供两种不同操作：

- **从当前项目移除**：仅删除项目与素材之间的引用，不影响全局素材及其他项目。
- **从全局素材库删除**：素材进入回收站，并从所有项目中隐藏或移除。

回收站需要支持：

- 查看已删除素材。
- 恢复素材。
- 彻底删除素材。

回收站保留期限和彻底删除权限仍待确认。

### 3.6 自动对比

- 系统根据项目拥有的维度数量选择一维、二维或三维对比视图。
- 每个项目维度对应空间中的一条坐标轴。
- 图片在每条轴上的坐标来自该图片在当前项目中的维度值。
- 一个维度时，图片按照数值从 `0.00` 到 `10.00` 排列在单轴上。
- 两个维度时，图片按照两个维度值定位在二维平面中。
- 三个维度时，图片按照三个维度值定位在三维空间中。
- 调整图片的维度 Slider 后，图片在对比视图中的位置同步更新。

### 3.7 自由画布

- 自由画布属于 MVP 核心功能。
- 提供画布，用于自由摆放图片素材并进行视觉对比。
- 一个项目可以创建多个自由画布。
- 每个画布需要持久化保存图片引用、坐标、尺寸、层级等布局数据。
- 局域网内的多人可以打开同一画布并共同编辑。
- 一名用户对画布布局的修改需要同步给其他正在查看该画布的用户。

### 3.8 项目管理

- 服务端支持创建新项目。
- 支持重命名项目。
- 支持删除项目。
- 删除项目只删除项目数据及素材引用，不删除全局素材文件。
- 支持复制项目。
- 复制项目时复制项目维度配置。
- 是否同时复制项目素材引用和自由画布仍待确认。
- 项目信息保存在服务端，包括项目基本信息、素材引用、项目维度、素材维度值和自由画布布局。
- 浏览器客户端不在用户本地持久化保存项目信息。
- 服务端数据库是项目信息的唯一权威数据源。

## 4. 团队协作

- MVP 不提供用户注册、登录和身份验证。
- 所有能访问服务地址的局域网用户均可进入系统。
- 所有人共用同一个全局素材库和项目列表。
- 局域网用户均可查看项目、上传图片、修改 Metadata 和编辑自由画布。
- MVP 不区分管理员、编辑者和只读成员。
- 由于没有用户身份，MVP 暂不记录具体操作人。
- 自由画布需要支持多人共同编辑和状态同步。

## 5. 初步数据关系

```text
素材 Asset 1 ─── 1 Metadata
    │
    ├── N:M ── 项目 Project
    │             │
    │             └── 1:N ── 项目维度 ProjectDimension
    │                              │
    │                              └── 维度赋值 AssetDimensionValue
    │
    └── N:M ── 对比画布 Canvas
```

- `Asset` 是全局唯一的素材记录。
- `Metadata` 保存素材自身的全局标签及其他全局属性。
- `ProjectAsset` 保存项目与素材的引用关系。
- `ProjectDimension` 保存仅在一个项目中有效的维度定义。
- `AssetDimensionValue` 保存某个项目内，素材在某个维度下的值。
- `CanvasItem` 保存画布对素材的引用及布局信息。
- 项目和画布均不拥有或复制素材文件。

## 6. 部署、存储与性能

### 6.1 MVP 部署

- 首版在一台本地服务器设备上运行应用服务、数据库和文件存储。
- 局域网内的设备通过浏览器访问。
- 所有业务数据均保存在服务端；访问者的电脑和浏览器不保存项目数据或素材主数据。
- 客户端仅保留页面运行期间需要的临时状态；刷新后重新从服务端读取。
- MVP 跑通后，需要能够迁移到公司 NAS 或其他内部服务器。
- 存储路径和服务配置不应硬编码，便于未来迁移。
- MVP 暂不实现自动备份。

服务端持久化内容包括：

- 全局素材记录与 Metadata。
- 原始图片与缩略图。
- 项目信息及项目与素材的引用关系。
- 项目维度定义及每张图片的维度值。
- 自由画布及其布局数据。

### 6.2 文件与缩略图

- 服务器保存原始图片。
- 图片上传成功时生成独立缩略图。
- 网格、维度空间等高频浏览场景优先加载缩略图。
- 放大查看时可以加载更高分辨率图片或原图。
- 暂不设置素材数量或总存储容量上限。
- 浏览接口需要支持分页或按需加载，避免一次加载全部原图。

## 7. 当前技术方向

### 7.1 素材管理基础

- MVP 选择 ResourceSpace 作为全局素材管理基础。
- 优先通过 ResourceSpace API 和扩展机制进行集成，避免直接大规模修改其核心代码。
- ResourceSpace 负责：
  - 原始图片与缩略图管理。
  - 图片上传和文件读取。
  - 全局素材记录。
  - 全局 Metadata 与自由标签。
  - 素材搜索和重复检测所需的基础数据。
- ResourceSpace 中的用户体系不直接暴露给 MVP 局域网用户。
- artDatabase 服务端使用内部服务身份访问 ResourceSpace API，API 密钥不得发送到浏览器客户端。

### 7.2 artDatabase 扩展层

ResourceSpace 标准能力之外的业务由 artDatabase 自行实现：

- 项目及项目复制。
- 项目与素材的引用关系。
- 每个项目最多三个维度的定义。
- 每张图片在不同项目维度下的独立数值。
- 一维、二维和三维空间展示。
- 多个自由画布及其持久化布局。
- 局域网内的多人实时画布同步。

### 7.3 前端组件候选

- 三维空间暂定使用 Three.js 实现。
- 自由画布暂定基于 Excalidraw 进行集成和定制。
- 多人实时同步暂定使用 Yjs 与 WebSocket；最终方案需要通过技术验证确定。

### 7.4 许可证边界

- ResourceSpace 使用 BSD-style 开源许可证，可以进行修改和二次开发。
- 衍生项目继续使用 `artDatabase` 名称，不使用 ResourceSpace 注册商标作为产品名称。
- 保留上游版权与许可证声明。

## 8. 当前明确不做

- 暂不提供图片裁剪、调色、加字等在线媒体编辑能力。
- 暂不提供 Metadata 历史版本。
- 暂不复制素材文件到各个项目中。
- 暂不支持视频和音频。
- 暂不支持批量上传。
- 暂不提供用户账号、登录和权限分级。
- 暂不提供自动备份。

## 9. 待确认问题

### 标签与自动对比

1. 一维、二维、三维视图中的图片重叠时，采用堆叠、自动避让还是聚合展示？
2. 标签筛选和维度视图是否可以同时使用？

### 项目页面与筛选

1. Hover 放大预览采用卡片原位放大、浮层预览还是跟随鼠标的放大镜？

### 上传流程

1. 完全重复素材使用文件哈希判断是否可以满足需求？
2. 重复提醒时，是否需要展示并允许直接引用已有素材？
