# artDatabase 技术验证计划

> 文档版本：v0.2  
> 文档日期：2026-08-14  
> 状态：验证一通过，artDatabase 实例已接入 ResourceSpace  
> 依据：[v0.1 需求说明](./2026-08-14_v0.1_需求说明.md)

## 1. 验证目标

在完整产品开发前，通过可重复的纵向技术验证确认以下高风险链路可行：

1. artDatabase 服务端能够安全集成 ResourceSpace，并完成图片、Metadata、缩略图和删除恢复操作。
2. 完全重复图片可以在正式上传前被识别，同时允许用户引用已有素材或继续创建新素材。
3. Excalidraw、Yjs 与 WebSocket 能够完成多人画布同步和服务端持久化。
4. 一维、二维和三维视图在预期素材规模下保持可用。
5. 项目、素材引用、维度和画布的数据约束能够由服务端与数据库共同保证。

## 2. 验证原则

- 每项验证必须可通过命令重复执行，不能只依赖手工观察。
- 验证过程保存配置、测试输入、日志和结果摘要，但不提交密钥或测试原图。
- 浏览器只保存页面运行期间的临时状态，服务端数据才是权威来源。
- ResourceSpace 作为独立系统，只通过 API 接入，不直接读取或修改其数据库表。
- 一个验证项通过后才进入依赖它的正式功能开发。

## 3. 验证一：ResourceSpace 集成

### 3.1 测试输入

- 图片 A：原始图片。
- 图片 B：与 A 字节完全相同，但文件名不同。
- 图片 C：视觉内容相同，但重新导出，文件字节不同。

测试文件由脚本生成或放置在忽略提交的临时目录中。

### 3.2 验证步骤

1. 使用 Docker Compose 启动 ResourceSpace 与 MariaDB。
2. 创建 artDatabase 专用的 ResourceSpace 服务账号和 API 密钥。
3. 配置 MVP 所需的 Metadata 字段及图片资源类型。
4. 使用服务端验证脚本调用 ResourceSpace API：
   - 检查系统状态。
   - 创建素材记录。
   - 通过 multipart 上传单张图片。
   - 写入名称、自由标签、描述、备注和来源链接。
   - 读取素材及 Metadata。
   - 获取缩略图或预览图。
   - 搜索素材。
   - 删除并恢复素材。
5. 对 A、B、C 计算完整文件 SHA-256。
6. 验证 A 与 B 被识别为完全重复，C 不被识别为完全重复。
7. 验证“引用已有素材”和“仍然上传新素材”两个分支。
8. 重启全部服务，再次读取素材、Metadata 和缩略图。
9. 模拟上传失败，确认不会遗留空 ResourceSpace 记录。

### 3.3 通过标准

- A、B 的完整 SHA-256 相同，C 的 SHA-256 不同。
- 重复检查发生在正式创建素材之前。
- 选择引用已有素材时不创建 ResourceSpace 新记录。
- 选择继续上传时允许存在两条指向不同 ResourceSpace 记录的素材。
- ResourceSpace API 用户和密钥只存在于服务端配置中。
- 原图、Metadata 和缩略图在服务重启后仍可读取。
- 失败流程完成补偿清理，不留下无文件的素材记录。
- 验证命令退出码为 0，并生成结果摘要。

### 3.4 证据

- 环境配置：`infra/resourcespace/`
- 验证脚本：`scripts/validation/resourcespace/`
- 执行结果：`validation-results/resourcespace/`

## 4. 验证二：Excalidraw 与 Yjs 多人画布

### 4.1 验证步骤

1. 创建只支持图片添加、移动、缩放、删除和层级调整的最小画布页面。
2. 两个浏览器连接同一个 `canvasId` 和 Yjs room。
3. 浏览器 A 移动图片，观察浏览器 B 的同步结果。
4. 两端同时移动不同图片，确认两个修改均保留。
5. 两端同时移动同一图片，确认最终状态一致。
6. 刷新浏览器，确认画布从服务端恢复。
7. 重启协作服务和数据库，再次确认画布恢复。
8. 模拟断网、离线修改和重新连接。
9. 检查 WebSocket 数据，确认只同步元素结构和 `assetId`，不传输原图 Base64。

### 4.2 通过标准

- 局域网内的同步延迟体感低于约 300ms。
- 所有连接端最终状态一致。
- 服务重启后画布能够恢复。
- 图片原文件只存在于 ResourceSpace，画布只保存引用。
- localStorage 和 IndexedDB 中没有项目权威数据。
- 同一元素并发修改按 MVP 约定的最后写入结果收敛。

## 5. 验证三：一维、二维和三维性能

### 5.1 数据规模

分别生成 100、500 和 1000 条模拟素材，并使用真实尺寸的缩略图。

### 5.2 验证场景

- 网格滚动和分页加载。
- 多个全局标签使用 OR 逻辑筛选。
- 一维轴排列。
- 二维平面缩放和平移。
- 三维空间旋转、缩放和平移。
- Slider 修改后素材位置更新。
- 大量素材坐标相同时的堆叠或聚合展示。

### 5.3 通过标准

| 素材量 | 目标 |
| --- | --- |
| 100 张 | 操作流畅，通常保持接近 60 FPS |
| 500 张 | 交互保持可用，无明显长时间阻塞 |
| 1000 张 | 页面不崩溃，可通过按需渲染继续操作 |

## 6. 验证四：数据模型与事务

必须通过自动化测试验证：

- 同一素材不能重复加入同一项目。
- 同一项目最多创建三个维度。
- 维度值不能小于 `0.00` 或大于 `10.00`。
- `(projectId, assetId, dimensionId)` 组合唯一。
- 素材加入项目后自动获得当前全部维度的默认值 `5.00`。
- 项目新增维度后，已有素材自动获得该维度默认值 `5.00`。
- 删除项目不删除全局素材。
- 从项目移除素材不影响其他项目。
- 全局删除、恢复和彻底删除遵循最终确定的引用恢复规则。

## 7. 最终纵向验收

使用至少两台局域网设备完成以下流程：

1. 创建项目和两个项目维度。
2. 上传一张图片并填写 Metadata。
3. 在另一台设备查看同一图片。
4. 修改标签和维度 Slider。
5. 查看二维视图中的位置变化。
6. 将图片拖入自由画布。
7. 两台设备同时编辑画布。
8. 重启全部服务。
9. 确认项目、素材、Metadata、维度和画布全部恢复。

计划中的统一验证入口：

```bash
docker compose up -d
pnpm test
pnpm test:integration
pnpm test:e2e
```
