## 1. 需求原文

用户 2026-11-07 提出：

1. 只想在**维度预览的画板**里增加“AI 自动标记维度”，和其他画板没有关联。
2. 新增一个按键。点击后，**维度画板中的所有图片一次发送给大模型**，让大模型判断维度；**返回一次就应用一次修改**。
3. 大模型修改期间**可以编辑维度信息**，以**最新更新的维度信息**为准。
4. 在**左下角**新增一个“更新提示”，表示当前正在执行 AI 自动标签。

---

## 2. 目标与要解决的问题

现在维度值只能靠人一张张拖、或在详情里一个个拉滑块。一个 Page 有几十张图、两三个维度时，初始化成本很高。

本需求要提供一条“**先让 AI 摆一版，人再微调**”的路径：

- 入口只出现在维度预览；
- 一次触发覆盖当前 Page 的全部图片；
- AI 结果分批回来、分批落库、分批反映到画布，不等全部跑完；
- 人随时可以改，改过的坐标 AI 不再覆盖；
- 全过程有可见但不打扰的进度提示。

## 3. 用户可见行为（详细）

### 3.1 入口

- 位置：维度预览顶部工具栏，放在“双指平移 · 捏合缩放”提示与缩放控件之间（`DimensionPreview.tsx` 工具栏，约 1800 行）。
- 形态：带 `Sparkles` 图标的文字按钮，文案 **“AI 标注维度”**；窄屏只显示图标，`title`/`aria-label` 保留完整文案。
- 运行中：按钮禁用，文案变 **“标注中…”**，并显示 `Spinner`。
- 游客（`readOnly`）：不渲染按钮。

### 3.2 前置条件与禁用态

| 条件 | 按钮状态 | 提示 |
| --- | --- | --- |
| 当前 Page 没有维度 | 禁用 | “请先添加维度” |
| 当前 Page 没有图片素材（只有视频或空 Page） | 禁用 | “当前 Page 没有可标注的图片” |
| 当前没有选中任何预览维度 | 禁用 | “请先选择至少一个维度” |
| 已有 AI 任务在跑（本机或同 Page 其他人） | 禁用 | “AI 正在标注当前 Page” |
| 坐标还有未同步的本地修改 | 点击时先等待同步；仍失败则提示 | “坐标正在保存，请稍后再试” |
| AI 服务未配置 | 允许点击，但立即报错 | “未配置 AI 服务，请联系管理员在「AI 服务配置」中设置” |
| 游客 | 不显示 | — |

> AI 服务配置目前只有管理员可见、可改；普通成员可以使用已配置好的服务，但看不到配置内容。这是现有规则，本次不改。

### 3.3 点击后的完整时序

1. 前端先把当前 Page 的待同步坐标 `flush()` 掉，确保服务端拿到的是用户最新值。
2. 服务端校验：登录、Page 属于该项目、有维度、有图片、AI 已配置、没有同 Page 任务。
3. 服务端为本次任务生成 `jobId`，建立“当前 Page 任务锁”。
4. 服务端按顺序读图、压缩、分批调用视觉模型（默认每批 4 张）。
5. 每批模型返回后：
   - 校验、换算、过滤掉“用户已经改过”的坐标；
   - 在一个事务里写入 `preview_dimension_values`，并把 `preview_pages.revision` +1；
   - 立即通过 NDJSON 流向客户端推送一条 `applied` 事件。
6. 客户端收到一条 `applied` 就更新一次本地 `previewPage`（素材坐标、`valueRevs`、`revision`），画布上的图片随之移动。
7. 全部批次结束：推送 `done`，释放任务锁，左下角提示消失，底部 toast 汇总结果。
8. 中途取消/切页/关页面：客户端中止流；服务端在下一批开始前停止；已经应用的批次保留。

### 3.4 左下角“更新提示”

- 位置：预览工作区（`.preview-workspace`）左下角，距左、距下各 16px；在场景之上、弹窗/详情抽屉之下。
- 形态：白底、细边框、圆角胶囊/小卡片，带 `Spinner`，`role="status"`、`aria-live="polite"`。
- 文案示例：
  - 运行中：`AI 自动标记中 · 3/12`
  - 有批次失败：`AI 自动标记中 · 3/12（1 批失败）`
  - 取消中：`正在取消…`
- 右侧提供一个小 `X` 取消按钮（`aria-label="取消 AI 标注"`），点击后中止任务；已应用结果不回滚。
- 运行结束、失败或取消后提示消失；结果用现有底部 toast 汇总（不新增第二个 toast）。
- 不遮挡右下角同步圆点（`SyncStatusDot`），不遮挡底部居中的 toast；专注模式下同样可见。
- `prefers-reduced-motion` 下不转圈，只显示静态图标。

### 3.5 运行中编辑（本需求最关键的部分）

运行中允许用户做以下操作，行为如下：

| 用户操作 | 行为 |
| --- | --- |
| 1D/2D 拖动图片改坐标 | 立即生效并进入本地同步队列；AI 之后对同一坐标的写入被跳过；用户值保留 |
| 在素材详情里拖维度滑块 | 同上，按“素材 + 维度”坐标粒度保护 |
| 编辑维度两端名称 | 该维度**剩余批次**不再应用（避免用旧语义判断新名称）；已应用的批次保留 |
| 新增维度 | 新维度不参与本次任务，保持中点；可通过再次点击按钮单独标注 |
| 删除维度（含 5 秒撤销窗口内） | 该维度的 AI 结果跳过；撤销恢复维度后也不会补写，需要重新运行 |
| 从 Page 移除素材 / 软删除素材 | 该素材的 AI 结果跳过；已应用的保留 |
| 运行中把新素材加入 Page | 不参与本次任务，保持中点；需要再跑一次才标注 |
| 切换选中轴、缩放、平移、象限隔离、模糊、专注模式 | 只改视图，不影响任务 |
| 打开素材详情 | 可以正常查看/编辑；AI 对正在编辑的坐标不回填输入框，用户保存后覆盖 |
| 再次点击 AI 按钮 | 按钮禁用，不能并发 |
| 切换 Page / 项目 / 离开维度预览 | **取消当前任务**（推荐，见 Q5）；已应用的结果保留 |

**“最新更新为准”的准确含义：**

- 同一坐标：**用户在这次任务开始之后改过，AI 就不再写它**；用户改得比 AI 晚，用户赢；用户改得比 AI 早（AI 条件写失败），也是用户赢。
- 不同坐标：互不影响，AI 照常写。
- 维度定义：名称变更视为该维度语义已变，剩余批次跳过；删除则跳过。
- 不采用“最后写入赢”这么粗的规则，避免 AI 把用户刚拖好的图又拽走。

### 3.6 完成 / 失败 / 取消

| 结果 | 表现 |
| --- | --- |
| 全部成功 | toast：“AI 已更新 12 张图片的 3 个维度” |
| 部分成功 | toast：“AI 已更新 10 张图片；2 张因图片读取失败被跳过；1 个坐标因你已手动修改而保留” |
| 有批次失败 | 其他批次继续；结束时汇总失败批次数与原因（最多展示第一条） |
| AI 未配置 / 鉴权失败 | 立即失败，toast 指向管理员检查 AI 服务配置；不产生任何写入 |
| 用户取消 | toast：“已取消 AI 标注，已应用的结果保留” |
| 切换 Page / 离开 | 同上，可提示“AI 标注已取消” |
| 服务重启 / 网络断开 | 流中断，toast：“AI 标注中断，请重试”；已写入的批次保留 |
| 维度/Page 在运行中被删除 | 后续批次跳过或 404，结束时提示；不恢复已删除数据 |

### 3.7 明确不改变的东西

- 不改素材的**全局标签**、描述、备注、来源链接；本功能只写维度值。
- 不改自由画板、素材库、上传、标签管理、账号等任何模块。
- 不改维度预览已有的拖动、聚堆、景深、象限隔离、快捷键、撤销栈、本地优先同步规则。
- 不改维度值的界面刻度：仍然是 `-100～100` 的整数，中点 `0`。
- 不新增“AI 标注”按钮到素材详情页（现有单图 AI 打标是**标签**，不是维度，两者不要混）。
- 不做后台任务：离开页面不继续跑（推荐，见 Q5）。

## 4. 范围与非目标

### 4.1 范围

- 当前打开的一个维度 Page。
- 该 Page 中的全部**图片**素材（不含视频）。
- 该 Page 的全部维度（推荐；见 Q2）。
- 服务端调用已配置的 OpenAI 兼容视觉模型。
- 结果写入该 Page 的 `preview_dimension_values`。

### 4.2 非目标

- 不跨 Page、不跨项目、不批量跑多个 Page。
- 不生成标签、描述或 Metadata。
- 不做“AI 自动建维度”（只给已有维度打值）。
- 不做实时多人协同推送；沿用现有 30 秒兜底刷新与本地优先同步。
- 不做整批撤销（见 Q7）。
- 不做任务历史/审计表（见 Q8）。
- 不做按用户隔离、配额、计费统计。

## 5. 关键规则（建议写死）

| 编号 | 规则 |
| --- | --- |
| R1 | **只作用于当前 Page**：请求必须带 `projectId + pageId`，服务端校验归属；不触碰其他 Page、其他项目。 |
| R2 | **只发图片**：视频素材跳过并计入“跳过”；缺失原图/无法解码的素材跳过，不阻塞其他图。 |
| R3 | **维度按 ID 对齐**：模型输出用短别名（`d1`、`d2`），服务端映射回真实维度 ID；不靠名称匹配。 |
| R4 | **值域**：模型输出 `-100～100` 的整数；服务端换算为 `0～1000`（`value = (ai + 100) × 5`）；小数四舍五入，越界截断。 |
| R5 | **一次返回一次应用**：一个模型响应 = 一个批次；一个批次 = 一次数据库事务 + 一条 `applied` 事件 + 一次本地状态更新。不是逐 token、也不是逐图。 |
| R6 | **用户编辑优先**：以任务开始时每个坐标的 `last_rev` 为期望值做条件更新；条件不满足（用户或其他客户端已改）就跳过该坐标，不覆盖。 |
| R7 | **维度定义变更优先**：开始后维度被删除 → 跳过；两端名称被改 → 该维度剩余批次跳过；新增维度不参与。 |
| R8 | **失败隔离**：单批失败只影响该批；其他批继续；结束时汇总。 |
| R9 | **幂等**：同一批结果重复应用不会产生重复行；值相同也只会让 `last_rev` 变化一次，不会累加数据。 |
| R10 | **同一 Page 单任务**：服务端内存锁；第二个请求返回 409；任务结束/断开释放。 |
| R11 | **全局并发上限**：同一进程内同时只跑 1 个 AI 维度任务（不同 Page 也排队/拒绝），避免同一个 AI key 被多路批量请求打爆限流；后续可改为队列。 |

## 6. AI 提示词与结果

### 6.1 输入

每批包含：

- 当前 Page 的维度列表（短别名 + 左端名称 + 右端名称）；
- 本批图片（短别名 + 压缩后的 JPEG data URI）；
- 每张图片的编号与别名对应关系。

图片沿用现有 AI 打标链路：读取原图 → `sharp` 旋转/缩放（最长边 1024）→ 白底 → JPEG 80。单张失败跳过。

### 6.2 提示词模板（建议）

```text
你是图片素材的维度标注助手。当前维度 Page 有以下维度，每个维度是一条从左端到右端的连续轴：

- d1：左端「抽象」 ↔ 右端「具象」
- d2：左端「冷色」 ↔ 右端「暖色」
- d3：左端「静态」 ↔ 右端「动态」

下面按顺序给出 4 张图片：
- 图 1：a1
- 图 2：a2
- 图 3：a3
- 图 4：a4

请为每张图片的每个维度给出一个 -100 到 100 的整数：
- -100 表示完全靠近左端，100 表示完全靠近右端；
- 0 表示中性、无法判断或与该维度无关；
- 必须使用整数，不要输出小数；
- 每张图片都要给出全部维度，不要遗漏；
- 只输出 JSON，不要解释、不要 Markdown 代码块。

输出格式：
{"items":[{"asset":"a1","values":{"d1":-30,"d2":40,"d3":0}}, ...]}
```

### 6.3 输出格式

```json
{
  "items": [
    { "asset": "a1", "values": { "d1": -30, "d2": 40, "d3": 0 } },
    { "asset": "a2", "values": { "d1": 65, "d2": -10, "d3": 80 } }
  ]
}
```

### 6.4 校验与容错

- 顶层接受 `{ items: [...] }` 或直接数组；两种都兼容。
- `asset` 必须是本批别名；`values` 的键必须是本批维度别名；否则忽略该条/该键。
- 值必须是有限数字；四舍五入；小于 -100 截断为 -100，大于 100 截断为 100。
- 缺失的维度键 = 不修改该坐标（不默认写 0）。
- 同一素材重复出现：后一条覆盖前一条。
- 解析失败：用同一批图片重试一次（temperature 0，并追加“上一次输出不是合法 JSON，请只输出 JSON”）；仍失败则记为该批失败。
- 模型返回 401/403：整个任务立即中止（配置问题，重试无意义）。
- 429/5xx/超时：同一批退避重试 1 次；仍失败记为该批失败，继续下一批。

### 6.5 分批（建议）

- 默认 **4 张/批**，顺序执行；批间可加 200ms 间隔，降低限流风险。
- 一个 Page 的图片数超过 20 张时，点击后先确认：“将把 N 张图片发送给 AI，预计需要约 X 秒，是否继续？”
- 单次任务硬上限建议 **200 张**；超过时返回明确错误，提示分批或减少 Page 素材（见 Q6）。
- 维度数建议上限 **20 个/次**；超过时提示先精简维度（Page 维度本身不限制，只限制本次任务）。
- 图片会发送到管理员配置的 AI 服务（与现有单图 AI 打标相同）；大批量确认框里要写明这一点，避免用户误以为只是本地计算。
- 单批 `max_tokens` 建议按 `200 + 12 × 图片数 × 维度数` 估算，上限 4000；被截断按“解析失败”重试一次。
- 模型温度固定 `0`，减少同一批图片的随机波动。

> “所有图片一次发送”在本文中解释为“**一次点击覆盖所有图片**”，而不是“一个 HTTP 请求装下所有图片”。原因见 §7.2 与 Q3。

## 7. 技术方案

### 7.1 数据流

```text
用户点击
  → 前端 flush 待同步坐标
  → POST /api/preview-pages/ai-dimensions { projectId, pageId }
  → 服务端校验 + 建任务锁
  → 读取 Page 维度、图片素材、每个坐标的 last_rev 快照
  → 分批：读图/压缩 → 调视觉模型 → 解析/校验
       → 事务：条件 UPDATE + revision +1
       → NDJSON 推送 applied
  → 客户端逐条读取 NDJSON：
       → 过滤本地 pending 坐标
       → 更新 previewPage.assets[].dimensionValues / valueRevs
       → 更新 revision
       → 更新左下角进度
  → done：释放锁、toast 汇总
```

### 7.2 为什么必须分批

1. **模型/请求限制**：几十张 1024px 图片的 base64 会超过单次请求体积与上下文；实际不可行。
2. **准确率**：一次给模型太多图，维度的相对判断会明显下降；小批更稳。
3. **增量应用**：只有分批才能在“第一张图结果回来”时就开始改画布，满足“返回一次应用一次”。
4. **失败隔离**：一批失败不影响其他批。

因此“一次发送”只作为**产品语义**保留：用户只点一次、只看到一次任务；网络层按批发送是内部实现。

### 7.3 服务端接口

```http
POST /api/preview-pages/ai-dimensions
Content-Type: application/json

{
  "projectId": "p_1",
  "pageId": "pg_1"
}
```

可选参数（用于 Q2 的“只标选中轴”方案）：

```json
{ "dimensionIds": ["d_1", "d_2"] }
```

响应：`Content-Type: application/x-ndjson`，逐行 JSON。

```json
{"type":"start","jobId":"...","total":12,"batchSize":4,"dimensions":3,"model":"qwen3-vl-plus"}
{"type":"progress","done":4,"total":12}
{"type":"applied","batch":1,"updates":[{"assetId":"a_1","dimensionId":"d_1","value":350,"lastRev":44}],"skipped":[{"assetId":"a_2","dimensionId":"d_1","reason":"value_changed"}],"revision":44}
{"type":"batch_failed","batch":2,"assetIds":["a_5","a_6"],"message":"AI 服务返回 429"}
{"type":"done","appliedAssets":10,"skippedCoordinates":2,"failedBatches":1,"revision":46}
```

流开始前的错误用普通 JSON + 状态码：

| 状态 | 场景 |
| --- | --- |
| 400 | 未配置 AI 服务 / 没有维度 / 没有图片 / 超过上限 / 请求体不合法 |
| 401 | 未登录 |
| 403 | 游客只读 |
| 404 | Page 不存在或不属于该项目 |
| 409 | 当前 Page 已有 AI 任务，或已有全局 AI 任务（全局并发上限） |
| 502 | AI 服务不可用（流开始前就能判断时） |

流开始后的错误只能通过 `batch_failed` / `done` 表达，不能再改 HTTP 状态码。

### 7.4 条件写库（“最新更新为准”的实现）

任务开始时读取当前 Page 所有坐标的 `last_rev`，作为期望值：

```sql
UPDATE preview_dimension_values
SET value = ?, last_rev = ?
WHERE page_id = ? AND asset_id = ? AND dimension_id = ? AND last_rev = ?;
```

- `changes = 0` → 该坐标在任务开始后被改过，加入 `skipped`，不覆盖。
- 每批只 bump 一次 `preview_pages.revision`，把新 revision 写入本批成功坐标的 `last_rev`。
- 每批一个事务（`BEGIN IMMEDIATE`），与现有 `PATCH /api/preview-values` 串行化。
- 维度名称快照：开始前记录每个维度的 `left_label/right_label`；应用前比对，变了就跳过该维度。
- 维度被删：`UPDATE` 影响 0 行或外键失败，跳过即可；不要因为单条失败回滚整批。
- 素材被移出 Page：同样跳过。

现有 `last_rev` 语义是“该坐标最后一次写入时的 Page revision”，由 `PATCH /api/preview-values` 维护（`preview-pages.js:239-245`）。本功能复用该语义，不新增列。

### 7.5 客户端状态与应用

新增 `app/src/useAiDimensionTag.ts`（或放在 `ArtDatabaseApp` 内的局部 hook）：

```ts
type AiDimensionState = {
  status: "idle" | "running" | "done" | "error";
  done: number;
  total: number;
  failedBatches: number;
  start: () => Promise<void>;
  cancel: () => void;
};
```

- 用 `fetch` + `response.body.getReader()` 读 NDJSON；`TextDecoder` 按行切分，处理跨 chunk 的半行。
- 每条 `applied`：
  - 对每个坐标，如果 `dimSync.isPending(assetId|dimensionId)` 为真 → 跳过本地应用；
  - 否则更新 `previewPage` 的 `dimensionValues` 与 `valueRevs`；
  - `revision = Math.max(current, event.revision)`。
- `done`：汇总 toast；`status = done`。
- `cancel`：`AbortController.abort()`；`status = idle`；toast。
- 切换 Page / 项目 / 卸载：`useEffect` cleanup 调 `cancel()`。
- 流读取失败：`status = error`，toast；已应用结果不回滚。

`DimensionPreview` 只负责按钮与左下角提示，通过 props 接收 `aiTag` 状态：

```ts
aiTag?: {
  status: "idle" | "running" | "done" | "error";
  done: number;
  total: number;
  failedBatches: number;
  start: () => void;
  cancel: () => void;
};
```

> 应用逻辑必须放在 App（或 hook）里，因为 `previewPage`、`dimSync`、`setMessage` 都在 App；`DimensionPreview` 只负责展示。

### 7.6 生命周期与取消

| 事件 | 行为 |
| --- | --- |
| 用户点取消 | abort 流；服务端在下一批开始前停止；已应用保留 |
| 切换 Page | 取消；恢复按钮；toast |
| 切换项目 / 返回主页 | 取消 |
| 浏览器标签关闭 / 刷新 | 连接断开；服务端停止；已应用保留 |
| 服务端重启 | 流断开；客户端提示中断；任务锁随进程消失 |
| 同 Page 第二个用户 | 409；按钮提示“AI 正在标注当前 Page” |
| 不同 Page 同时发起（全局并发上限） | 409；提示“已有 AI 标注任务在执行，请稍后再试”（后续可改为排队） |
| Page 被删除 | 下一批 404；任务结束；提示 |

### 7.7 失败与重试

| 失败 | 处理 |
| --- | --- |
| 单张图片读取/解码失败 | 跳过该素材，继续该批其他素材；计入 `skipped` |
| 模型超时 / 429 / 5xx | 该批重试 1 次；仍失败记 `batch_failed`，继续下一批 |
| 模型 401/403 | 整个任务中止；提示管理员检查 AI 配置 |
| 配置的是纯文本模型（不支持图片） | 模型返回 400；提示“当前模型不支持图片，请在 AI 服务配置中改用 VL 模型” |
| 模型返回非 JSON | 该批重试 1 次（追加“只输出 JSON”）；仍失败记 `batch_failed` |
| 数据库写失败 | 该批失败，继续下一批；记录日志 |
| 客户端断开 | 服务端停止，不再发起新批次 |

### 7.8 权限

- 未登录：401（现有全局规则）。
- 游客：403（现有“游客只允许 GET”规则；按钮也不显示）。
- 成员/管理员：可用；不需要管理员权限，因为 AI 配置由管理员预先保存。
- AI 配置仍仅管理员可读写（现有 `/api/ai-config` 规则）。

### 7.9 可选的“未配置”前置判断

现在 `GET /api/ai-config` 仅管理员可访问。若希望成员在按钮上就能看到“未配置”，可新增：

```http
GET /api/ai-config/status
→ { "configured": true }
```

只返回布尔值，不泄露 key/模型；所有登录用户可读。若不新增，则点击后由 400 错误提示，功能不受影响。

## 13. 风险与取舍

1. **成本与耗时**：整页图片都发给模型，Page 越大越贵、越慢。用确认框、上限和可取消控制；不做后台任务。
2. **模型准确率**：维度语义靠两端名称，名称太抽象时结果会不稳定；用户可随时改，AI 不覆盖用户改动。
3. **覆盖风险**：Q4 若选“全部覆盖”，会覆盖此前人工调过的值。建议在确认框/按钮 `title` 中写明“会覆盖当前 Page 的维度值”，或改为只填未改过的坐标。
4. **流式复杂度**：NDJSON 跨 chunk、半行、取消、服务重启都要处理；现有 `index.js` 已支持流式响应，技术上可行。
5. **并发一致性**：条件写依赖 `last_rev` 语义；任何绕过 `/api/preview-values` 直接写表的代码都会破坏保护。
6. **详情抽屉编辑**：AI 更新与抽屉本地输入状态可能竞争；实现时需保证“正在编辑的坐标不回填，保存后用户赢”。
7. **刷新/兜底拉取**：30 秒拉取可能把 AI 已写入的值带回来，这是正常的；未同步的本地坐标由 `mergePreviewPage` 保护。
8. **无撤销**：误点一次会覆盖全页；确认框与“用户改动优先”是缓解手段，不是撤销。
9. **任务锁是单进程内存锁**：符合当前单 Node 进程架构；未来多进程/多实例部署需换成数据库锁。
10. **AI 服务不可用**：现有单图 AI 打标已经会遇到；本功能只是放大影响面，错误提示要清楚。

## 14. 术语

| 术语 | 含义 |
| --- | --- |
| 维度 Page | 项目下的独立维度画板，拥有自己的素材集合、维度定义和坐标值 |
| 坐标 | 一个 `(page_id, asset_id, dimension_id)` 的值，界面范围 -100～100，存储 0～1000 |
| 批次 | 一次模型调用包含的若干张图片；默认 4 张 |
| `last_rev` | 该坐标最后一次写入时的 Page revision，用于判断“任务开始后有没有人改过” |
| 条件写 | `UPDATE ... WHERE last_rev = 快照值`，改过就不写 |
| pending | 本地已改、还没同步到服务端的坐标；由 `useDimensionSync` 维护 |
| NDJSON | 每行一个 JSON 的流式响应，用于“返回一次应用一次” |
