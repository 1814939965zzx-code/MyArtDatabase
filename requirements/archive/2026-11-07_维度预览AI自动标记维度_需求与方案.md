## 0. v2 相对 v1 的关键变化

先看这几条，避免拿旧版理解：

1. **不再是多图混判**：一次模型请求**只包含 1 张图片**，绝不把多张图混在一次判断里。任务内默认 **2 张并发**（两张各自独立的单图请求），不是“一张请求塞多图”。
2. **先弹确认框**：选择要标记的维度、选择“全部标记”还是“只标记选中维度当前为 0 的”，再开始。
3. **逐图锁定**：正在被 AI 处理的 1～2 张图显示 loading、暂时禁止改它们的维度；处理完成或超时后解锁。其他图不受影响。
4. **超时丢弃**：每张图有独立超时（默认 60 秒）；超时后立刻解锁，用户可以操作；如果模型之后才返回，结果直接丢弃，不写库。
5. **后台任务**：批量任务跑在服务端，刷新页面、切 Page、切项目、切到自由画板都不打断，直到跑完或被用户停止。
6. **胶囊按页面归属**：AI 胶囊只出现在维度预览、且只出现在任务所属的 Page；自由画板的同步状态只在自由画板，不跨 tab。
7. **可停止**：胶囊上有停止按钮，用户可随时停止整个批量任务（队列 + 正在处理的 1～2 张图）；已应用的结果保留。
8. **不是长连接**：客户端用轮询拿任务状态与增量结果，刷新后能恢复显示；任务状态只放内存（Q13 已确认），服务重启会中断任务、已写入的保留。
9. **先做单图**：素材详情里先提供“AI 标记这张图”，同步请求、无队列/无胶囊；批量在其后复用同一套单图逻辑。

## 2. 目标

现在维度值只能人工一张张拖、或在详情里拉滑块。一个 Page 有几十张图、几个维度时，初始化成本很高。

本需求提供“**先让 AI 摆一版，人再微调**”的路径：

- 只出现在维度预览；
- 一次触发覆盖当前 Page 的全部图片；
- 每张图独立判断、独立返回、独立落库；
- 处理哪张就锁哪张，处理完立刻解锁；
- 超时不等待，迟到结果丢弃；
- 人随时可以停止；刷新、切页不丢任务；
- 左下角胶囊只属于当前维度预览 Page。

## 3. 用户可见行为（详细）

### 3.1 入口

**3.1.1 单图入口（先做）**

- 位置：从维度预览打开素材详情，在“维度”区域顶部提供 **“AI 标记这张图”** 按钮（`Sparkles` 图标）。
- 只对图片素材显示；视频不显示；游客不显示。
- 点击后打开与批量共用的确认框，但只包含当前这一张图片：选择维度、选择 `all` / `zero`，确认后立即请求。
- 处理期间：按钮显示 loading，当前图片的维度滑块暂时禁用；其他图片、维度改名、视图操作不受影响。
- 成功：更新当前图片的维度值，toast 汇总；失败/超时：按钮恢复，维度滑块解锁。
- 单图请求是同步的：不产生批量胶囊，不进入批量队列；超时 60 秒，超时后不等待、不补写。

**3.1.2 批量入口**

- 位置：维度预览顶部工具栏，放在“双指平移 · 捏合缩放”提示与缩放控件之间。
- 形态：带 `Sparkles` 图标的文字按钮 **“AI 标注维度”**；窄屏只显示图标，`title` / `aria-label` 保留完整文案。
- 运行中：按钮禁用，文案 **“标注中…”**，带 `Spinner`。
- 游客（`readOnly`）：不渲染按钮。

批量入口禁用条件：

| 条件 | 提示 |
| --- | --- |
| 当前 Page 没有维度 | “请先添加维度” |
| 当前 Page 没有图片素材（只有视频或空 Page） | “当前 Page 没有可标注的图片” |
| 当前没有选中任何预览维度 | “请先选择至少一个维度” |
| 当前 Page 已有单图请求或批量任务在执行 | “AI 正在标注，请稍后再试” |
| 坐标还有未同步的本地修改 | 点击后先等待同步；仍失败提示“坐标正在保存，请稍后再试” |

### 3.2 确认弹窗

点单图或批量按钮后先弹确认框，不直接开跑。单图入口传入的 `assets` 只有当前这一张；批量入口传入当前 Page 的全部图片。

**A. 选择维度**

- 列出当前 Page 的全部维度，多选；默认全选。
- 每项显示“左端名称 ↔ 右端名称”。
- 一个都不选时，“开始标记”禁用。
- 只标记选中的维度，其他维度不动。

**B. 选择标记范围**

两个单选项：

1. **只标记未修改的（选中维度当前为 0）** —— 默认（已确认）。
   - 0 指界面值 0（存储值 500，中点）。
   - 按**坐标**粒度：某张图的某个选中维度是 0，才补这个坐标；不是 0 的不动。
   - 一张图只要还有一个选中维度是 0，就会被处理；一个都没有则跳过，不调模型。
2. **全部标记（会覆盖选中维度已有的值）**。
   - 选中维度不论当前是多少，都重新判断并覆盖。
   - 用醒目的提示说明“会覆盖这些图片已有的维度值”。

**C. 摘要与提示**

- 显示：`将处理 N 张图片 × M 个维度`、其中“只补 0”模式下实际需要处理的坐标数。
- 显示：`每张图片单独发送给 AI；处理期间该图片暂时锁定，其他图片仍可编辑。`
- 显示：`刷新或切换页面不会中断，任务会在后台继续；可随时在左下角停止。`
- 若“只补 0”模式下没有任何目标坐标：禁用开始，提示“选中维度没有需要标记的 0 值”。
- 若图片数超过 20：在摘要中给出预计时间（按每张 8～15 秒估算），不再二次确认。
- 单次任务硬上限 **200 张**；超过时在弹窗里提示并禁用开始，要求分批或减少 Page 素材。
- 维度数上限 **20 个/次**；超过时提示先精简本次选择（Page 本身不限）。

**D. 按钮**

- “取消” / “开始标记”。
- 单图确认后关闭弹窗，详情按钮进入 loading；批量确认后关闭弹窗，进入任务状态。两者都不出现第二个 toast。

### 3.3 任务时序

1. 用户在弹窗点“开始标记”。
2. 前端先 `flush()` 当前 Page 的待同步坐标，确保服务端拿到最新值。
3. `POST` 创建任务，立即返回 `jobId`（不等待模型）。
4. 服务端：
   - 校验登录、Page 归属、AI 配置、没有其他任务；
   - 固定本次的维度 ID 列表与模式（`all` / `zero`）；
   - 为每个“图片 + 选中维度”记录任务开始时的 `last_rev` 与当前值；
   - 生成待处理图片队列（只保留至少有一个目标坐标的图片）；
   - 在后台用 2 个 worker 按队列处理（最多 2 张同时请求模型）。
5. 每张图片：
   - 发送前再次检查它的目标坐标是否在任务开始后被用户改过；改过的坐标剔除；一个不剩就跳过这张图；
   - 调用模型（**请求里只有这一张图**）；
   - 服务端标记这张图为“处理中”，客户端轮询看到后显示 loading 并锁定这张图；
   - 模型返回 → 校验 → 条件写库 → 产生一条 `applied` 事件；
   - 解锁这张图，继续下一张。
6. 客户端每 800ms 轮询任务状态：
   - 读取 `inFlight` 更新 loading / 锁定；
   - 读取 `events` 增量更新坐标、`valueRevs`、`revision`；
   - 更新左下角进度。
7. 全部完成 / 被用户停止 / 全部失败：胶囊消失，底部 toast 汇总；已应用结果保留。

> “返回一次就应用一次修改”= **一张图片的模型响应返回一次，就把这张图片的维度值落库一次、界面更新一次**。不是逐 token，也不是等全部图片跑完。

### 3.4 单图处理中的 loading 与锁定

**显示：**

- 正在处理的 1～2 张图，各自在本体上叠加半透明遮罩 + 转圈（`Spinner`），表示“AI 正在修改这张图的维度”。
- 收起堆里包含这张图：堆右上角数量徽标旁显示一个小转圈；展开平面里对应卡片显示同样遮罩。
- 3D、1D、2D 都显示；图片缩放、旋转不影响遮罩。
- loading 期间该图的坐标 tag 可以保留，但降低不透明度，避免误读。

**锁定范围（按图片，不按整页）：**

| 操作 | 处理中的图片 | 其他图片 |
| --- | --- | --- |
| 1D/2D 拖动改坐标 | 禁止 | 允许 |
| 详情抽屉里的维度滑块 | 禁用（显示“AI 处理中”） | 允许 |
| 打开详情、编辑名称/标签/描述/备注 | 允许（只锁维度值） | 允许 |
| 维度改名、增删维度 | 允许 | 允许 |
| 缩放、平移、切轴、象限隔离、模糊、专注模式 | 允许 | 允许 |
| 从 Page 移除素材 / 软删除素材 | —（该图结果跳过） | 允许 |
| 把新素材加入 Page | —（不参与本次，保持中点） | 允许 |
| 再次点击 AI 按钮 | 禁止 | 禁止 |

- 锁定的实现以 `assetId` 集合为准（`inFlight`），不是全局开关。
- 如果用户在同一张图的详情抽屉里已经打开了滑块，处理开始时滑块变为禁用，不改写当前值。
- 超时或返回并应用后立即解锁。
- 已确认：只锁正在处理的 1～2 张图，不冻结整页；理由是不让整页在几十张图的处理期间不可用。

### 3.5 左下角胶囊

**归属：**

- 只出现在维度预览。
- 只出现在任务所属的 Page；切到其他 Page 不显示，任务继续在后台跑；切回来自动恢复显示。
- 同一 Page 的其他登录用户也会看到胶囊与 loading（他们轮询同一个任务）；停止按钮默认只对任务创建者和管理员可用，其他人看到只读进度。
- 自由画板的同步圆点只在自由画板；维度坐标同步圆点只在维度预览右下角；三者互不串台（见 §3.9）。

**形态：**

- 位置：`.preview-workspace` 左下角，距左、距下各 16px。
- 白底、细边框、圆角胶囊/小卡片，带 `Spinner`。
- `role="status"`、`aria-live="polite"`。
- 不遮挡右下角同步圆点、不遮挡底部居中 toast；专注模式下可见。
- 窄屏只显示“3/12”和停止按钮，文案可截断。
- `prefers-reduced-motion` 下不转圈，显示静态图标。

**内容：**

- 运行中：`AI 自动标记中 · 3/12`
- 有图片处理中：`AI 自动标记中 · 3/12 · 2 张处理中`（并发 >1 时显示数量）
- 有超时：`AI 自动标记中 · 3/12 · 1 张超时`
- 停止中：`正在停止…`
- 停止/完成/失败后胶囊消失。

**停止按钮：**

- 胶囊右侧一个 `X`/停止图标，`aria-label="停止 AI 标注"`。
- 点击后**立即**停止：清空队列、中止正在处理的请求、任务状态改为 `stopped`。
- 已应用的结果保留，不要求确认。
- toast：`已停止 AI 标注；已应用的 5 张图片保留`。
- 停止是唯一会中断任务的用户操作；刷新、切页、关标签页都不算。

### 3.6 超时

- 每张图片独立超时，默认 **60 秒**（可配置）；单图入口同样适用。
- 超时后：
  - 该图片标记为 `timed_out`，立即解锁；
  - 请求被 abort（如果底层仍返回，服务端在写库前检查状态并丢弃）；
  - 不写任何坐标；
  - 批量任务继续处理下一张；单图请求直接结束。
- 用户在看到超时后可以正常操作这张图的维度。
- 批量不逐张弹 toast，胶囊上累计“1 张超时”，结束时汇总；单图直接 toast“AI 超时，未修改”。
- 如果超时后模型才返回：**结果丢弃，绝不补写**。
- 如果整页所有图片都超时：任务结束，toast 提示“AI 没有响应，未修改任何维度”。

### 3.7 后台运行与恢复

- 批量任务在服务端运行，不依赖浏览器连接；单图请求是同步的，不进入后台。
- 刷新页面：新页面拉取 `GET job`，如果批量任务还在，恢复胶囊、进度、处理中图片的 loading 与锁定；页面坐标用 `GET /api/preview-page` 拉取，已应用的都在。
- 切到其他 Page / 项目 / 自由画板 / 主页：批量任务继续；胶囊只在所属 Page 显示；回来时恢复。
- 关闭标签页：批量任务继续；单图请求可能被浏览器中断，服务端若已完成写库则保留。
- 浏览器离线：批量任务继续（服务端跑）；客户端恢复网络后继续轮询，看到最新状态。
- 服务重启：内存中的批量任务丢失；客户端轮询得到 404 或 `job:null`，提示 `AI 标注已中断，已应用的维度保留`；不自动恢复。
- 同一时间只允许一个批量任务；同一 Page 同时只允许一个 AI 维度操作（单图或批量）；不同 Page 的单图请求可以并行。

### 3.8 完成 / 失败 / 停止 / 中断

| 结果 | 表现 |
| --- | --- |
| 全部成功 | toast：`AI 已标记 12 张图片的 3 个维度` |
| 部分成功 | toast：`AI 已标记 10/12 张；1 张超时；1 张因你已修改而跳过` |
| 有图片失败 | 继续其他图片；结束时汇总失败数；失败图片解锁 |
| 全部失败 | toast：`AI 标注失败，未修改维度` + 第一条原因 |
| 用户停止 | `已停止 AI 标注；已应用的 5 张图片保留` |
| 服务重启 / 任务丢失 | `AI 标注已中断；已应用的维度保留` |
| AI 未配置 / 401 / 403 | 任务立即结束，toast 指向管理员检查 AI 服务配置；不产生半套数据 |
| Page 被删除 | 任务结束；已删除的 Page 数据一并消失 |
| 维度全部被删除 | 任务无法继续，按“失败/停止”结束；已应用的保留 |

### 3.9 状态归属（不跨 tab）

| 位置 | 状态 | 出现范围 |
| --- | --- | --- |
| 自由画板右下角 | 画板同步圆点（`SyncStatusDot`） | 只在自由画板 |
| 维度预览右下角 | 维度坐标同步圆点 | 只在维度预览 |
| 维度预览左下角 | AI 自动标记胶囊（仅批量） | 只在维度预览，且只在任务所属 Page |
| 底部居中 | toast（结果/错误） | 全局，但由当前操作触发 |

- 单图入口不产生胶囊：只有详情按钮 loading + 该图维度滑块禁用；成功后 toast。
- 自由画板的同步状态不得出现在维度预览或其他 tab。
- 维度预览的 AI 胶囊不得出现在自由画板、素材库、主页。
- 维度坐标同步圆点与 AI 胶囊可以同时存在：右下是“坐标有没有存上”，左下是“AI 还在不在跑”。
- 建议给两个圆点补 `title`：`维度坐标同步` / `画板同步`，避免用户误认。

### 3.10 明确不改变的东西

- 不改素材的全局标签、描述、备注、来源链接；本功能只写维度值。
- 不改自由画板、素材库、上传、标签管理、账号等任何模块。
- 不改维度预览已有的拖动、聚堆、景深、象限隔离、快捷键、撤销栈、本地优先同步规则。
- 不改维度值的界面刻度：仍是 `-100～100` 的整数，中点 `0`。
- 不新增“AI 标注”按钮到素材详情页（现有单图 AI 打标是**标签**，不是维度）。
- 不做后台跨 Page 的全局进度面板；胶囊只属于一个 Page。

## 4. 范围与非目标

### 4.1 范围

- 当前打开的一个维度 Page。
- **批量**：该 Page 中的全部图片素材（含视口外、被隔离隐藏、堆内；不含视频）。
- **单图**：从详情打开的当前这一张图片（不含视频）。
- 用户在确认框里选中的维度（默认全部）。
- 服务端调用已配置的 OpenAI 兼容视觉模型。
- 结果写入该 Page 的 `preview_dimension_values`。

### 4.2 非目标

- 不跨 Page、不跨项目、不批量跑多个 Page。
- 不生成标签、描述或 Metadata。
- **不做 AI 自动创建维度**（只给已有维度打值）。
- 不做实时多人协同推送；沿用现有 30 秒兜底刷新与本地优先同步。
- 不做整批撤销（现有 Ctrl+Z 只撤销用户自己的拖动）。
- 不做任务历史/审计表。
- 不做按用户隔离、配额、计费统计。
- 不做“整页冻结”；只锁正在处理的 1～2 张图。

## 5. 关键规则（建议写死）

| 编号 | 规则 |
| --- | --- |
| R1 | **只作用于当前 Page**：请求必须带 `projectId + pageId`，服务端校验归属；不触碰其他 Page、其他项目。 |
| R2 | **只发图片**：批量 = 整页全部图片，单图 = 当前这一张；视频跳过；缺失原图/无法解码的素材跳过；不因一张失败阻塞其他图。 |
| R3 | **只标已有维度**：维度 ID 在任务开始时固定；不新增维度。 |
| R4 | **值域**：模型输出 `-100～100` 整数；服务端换算 `value = (ai + 100) × 5`（0～1000）；小数四舍五入，越界截断。 |
| R5 | **一次请求只含一张图**：模型请求里绝不同时出现两张图片；批量下一张图的响应 = 一次事务 + 一条事件 + 一次界面更新；单图直接同步返回。 |
| R6 | **标记范围**：`all` = 选中的全部维度；`zero` = 选中维度中当前值为 0（存储 500）的坐标；按坐标粒度。 |
| R7 | **最新编辑优先**：任务开始时逐坐标记录 `last_rev`；发送前剔除任务开始后被改过的坐标；响应写库时再做条件更新，改过就跳过。用户改过的坐标永远不被 AI 覆盖。 |
| R8 | **维度定义按最新**：每张图发送时使用当时的维度名称；若请求发出后名称变了，该维度结果在应用时跳过；维度被删则跳过；新增维度不参与。 |
| R9 | **逐图锁定**：正在处理的 1～2 张图显示 loading，并禁止拖坐标/改它们的维度滑块；其他图、其他维度定义、视图操作不受影响。 |
| R10 | **批量后台任务**：刷新、切页、切项目、关标签页都不中断；任务只在用户点停止、服务重启或不可恢复错误时结束。单图请求是同步的，不进入后台。 |
| R11 | **可停止**：批量胶囊停止按钮清空队列并中止处理中的请求；已应用结果保留，不回滚。单图入口不显示停止按钮，超时/失败即结束。 |
| R12 | **逐图超时**：默认 60 秒；超时解锁、不写库、继续下一张；迟到响应丢弃。 |
| R13 | **失败隔离**：单图失败/超时只影响该图；401/403 立即终止整个任务；429/5xx/解析失败重试 1 次后记失败。 |
| R14 | **并发边界**：同一时间只跑 1 个**批量任务**；同一 Page 同时只允许一个 AI 维度操作（单图或批量）；不同 Page 的单图请求可以并行，但仍受 AI 限流与同一 key 的配额约束。 |
| R15 | **范围外的绝不碰**：不写标签、不写自由画板、不写其他 Page、不改 Metadata。 |
| R16 | **单图入口**：只处理当前这一张图片，复用同一提示词/校验/条件写；同步返回，不建队列、不显示批量胶囊；超时 60 秒，迟到结果丢弃。 |

## 6. AI 请求与结果（单图）

### 6.1 目标坐标的计算

任务开始时：

1. 取当前 Page 的全部图片素材（`mime_type LIKE 'image/%'`，未软删）。
2. 取用户选中的维度（校验仍属于该 Page）。
3. 对每个图片 × 选中维度，记录：
   - 当前值 `value`；
   - 当前 `last_rev`（任务开始快照）；
   - 维度两端名称（发送时再取最新值）。
4. 生成目标集合：
   - `all`：全部选中维度；
   - `zero`：只保留 `value = 500`（界面 0）的坐标。
5. 生成队列：至少有一个目标坐标的图片；一张都没有的图片不发给模型，计入“跳过”。

发送每张图之前：

- 重新检查该图的目标坐标：如果某个坐标的 `last_rev` 已不等于任务开始快照 → 用户改过 → 从本次请求中剔除；
- 如果剔除后一个目标都不剩 → 跳过该图，不调模型；
- 剩余目标维度用**当前最新**的两端名称构建提示词。

> `all` 模式会覆盖任务开始前就存在的值；`zero` 模式只补 0，天然不覆盖已有值。确认框必须把这个差异写清楚。

### 6.2 提示词模板（单图）

```text
你是图片素材的维度标注助手。请只判断这一张图片在以下维度上的位置。

维度列表：
- d1：左端「抽象」 ↔ 右端「具象」
- d2：左端「冷色」 ↔ 右端「暖色」
- d3：左端「静态」 ↔ 右端「动态」

请为每个维度给出一个 -100 到 100 的整数：
- -100 表示完全靠近左端，100 表示完全靠近右端；
- 0 表示中性、无法判断或与该维度无关；
- 必须使用整数，不要小数；
- 每个维度都要给出，不要遗漏；
- 只输出 JSON，不要解释、不要 Markdown 代码块。

输出格式：
{"values":{"d1":-30,"d2":40,"d3":0}}
```

### 6.3 输出格式

```json
{ "values": { "d1": -30, "d2": 40, "d3": 0 } }
```

- 顶层也接受直接的对象（没有 `values` 包裹时，键即维度别名）。
- 只处理本次请求里出现的维度别名。

### 6.4 校验与容错

- 值必须是有限数字；四舍五入；`-100～100` 之外截断。
- 未知维度别名忽略。
- 缺失的维度 = 不修改该坐标（不默认写 0）。
- 解析失败：同一张图重试 1 次（temperature 0，追加“只输出 JSON”）；仍失败记该图失败。
- 模型 401/403：整个任务立即终止（配置问题）。
- 429/5xx/超时：该图重试 1 次；仍失败记该图失败，继续下一张。
- 单图 `max_tokens` 建议 `200 + 40 × 目标维度数`，上限 2000。
- 温度固定 `0`。

### 6.5 单图、并发、超时

- **每次模型请求只含 1 张图片**；这是硬规则，不能为了省请求把多张图塞进一个 messages。
- 队列按 Page 内素材顺序（或 Page 顺序）排列；默认 **2 路并发**处理（最多 2 张图同时在飞）。
- 并发数可配置（`AI_DIMENSION_CONCURRENCY`，默认 2，允许 1～2）；无论几路，**一次模型请求只含一张图**。设为 1 时退化为严格顺序。
- 每张图独立 60 秒超时（`AI_DIMENSION_ITEM_TIMEOUT_MS`）。
- 图片压缩沿用现有 AI 打标：最长边 1024、白底、JPEG 80；单张失败跳过。
- 图片会发送到管理员配置的 AI 服务（与现有单图 AI 打标相同）；确认框里要写明。

## 7. 技术方案

### 7.1 数据流

**单图（先做）：**

```text
用户点详情里的“AI 标记这张图”
  → 确认框：1 张图 + 维度多选 + all/zero
  → POST /api/preview-pages/ai-dimensions/single
  → 服务端：校验/快照 → 1 张图 → 模型请求（60s）→ 条件写库
  → 200 { updates, skipped, revision }
  → 前端直接更新 previewPage；按钮 loading、该图滑块锁定；无胶囊、无轮询
```

**批量：**

```text
用户点工具栏“AI 标注维度”
  → 确认框：维度多选 + all/zero
  → POST /api/preview-pages/ai-dimensions   → 202 { jobId }
  → 服务端后台任务：
       取 Page 维度/图片/坐标快照
       生成队列（每张图一条）
       for each 图片：
         发送前过滤被用户改过的坐标
         1 张图 → 模型请求（60s 超时）
         成功 → 条件写库（事务，revision +1）→ 记录 applied 事件
         超时/失败 → 记录 item 状态，继续
       结束 → done / stopped / error
  → 客户端每 800ms：
       GET /api/preview-pages/ai-dimensions/job?...&since=seq
       → 更新进度、inFlight loading/锁定、增量坐标
  → 胶囊显示；可 POST stop 随时停止
```

### 7.2 任务模型（服务端内存）

```ts
type AiDimensionJob = {
  id: string;
  projectId: string;
  pageId: string;
  userId: string;
  dimensionIds: string[];          // 任务开始时固定
  mode: "all" | "zero";
  status: "running" | "stopping" | "stopped" | "done" | "error";
  queue: string[];                // 待处理 assetId
  inFlight: Set<string>;          // 正在请求模型的 assetId
  items: Map<string, {
    status: "pending" | "running" | "applied" | "skipped" | "failed" | "timed_out";
    error?: string;
  }>;
  total: number;                  // 队列长度
  done: number;                   // 已结束（applied + skipped + failed + timed_out）
  applied: number;
  skipped: number;
  failed: number;
  timedOut: number;
  events: Array<{ seq: number; type: "applied"; updates: Array<{ assetId; dimensionId; value; lastRev }>; revision: number }>;
  seq: number;
  startedAt: string;
  finishedAt?: string;
  cancelRequested: boolean;
};
```

- `Map<pageId, job>` + 一个全局 `activeJobId`（R14）。
- 任务完成后在内存保留 10 分钟，供刷新/切回查询；新任务覆盖旧任务。
- 服务重启：Map 清空，任务中断；已写入 DB 的值保留。
- 不做数据库任务表（Q13 已确认：本轮只放内存）。

### 7.3 接口

#### 单图标记（先做）

```http
POST /api/preview-pages/ai-dimensions/single
Content-Type: application/json

{
  "projectId": "p_1",
  "pageId": "pg_1",
  "assetId": "a_1",
  "dimensionIds": ["d_1", "d_2"],   // 可选；省略时=全部维度
  "mode": "zero"                    // "zero" | "all"
}
```

响应：

```json
{
  "ok": true,
  "updates": [{ "dimensionId": "d_1", "value": 350, "lastRev": 44 }],
  "skipped": [{ "dimensionId": "d_2", "reason": "value_changed" }],
  "revision": 44
}
```

- 同步执行：服务端发 1 张图、等模型返回、条件写库后直接响应；不建任务、不产生胶囊。
- 每张图仍是独立请求；单图接口一次只接受 1 个 `assetId`。
- 任务/请求开始时记录该图每个目标坐标的 `last_rev`；写库时条件更新，用户改过的坐标跳过。
- 60 秒超时；超时返回 504（或 502），不写库；迟到响应丢弃。
- 同一 Page 已有批量任务或另一个单图请求 → 409。

#### 创建批量任务

```http
POST /api/preview-pages/ai-dimensions
Content-Type: application/json

{
  "projectId": "p_1",
  "pageId": "pg_1",
  "dimensionIds": ["d_1", "d_2"],   // 可选；省略时=全部维度
  "mode": "zero"                    // "zero" | "all"
}
```

响应：

```json
{ "jobId": "job_...", "total": 12 }
```

错误：

| 状态 | 场景 |
| --- | --- |
| 400 | 未配置 AI / 没有维度 / 没有图片 / 没有目标坐标 / 超过上限 / 参数不合法 |
| 401 | 未登录 |
| 403 | 游客只读 |
| 404 | Page 不存在或不属于该项目 |
| 409 | 已有批量任务，或当前 Page 有单图请求 |

#### 查询任务与增量

```http
GET /api/preview-pages/ai-dimensions/job?projectId=p_1&pageId=pg_1&since=12
```

响应：

```json
{
  "job": {
    "id": "job_...",
    "status": "running",
    "total": 12,
    "done": 3,
    "applied": 2,
    "skipped": 1,
    "failed": 0,
    "timedOut": 1,
    "inFlight": ["a_4"],
    "canStop": true,
    "items": [{ "assetId": "a_1", "status": "applied" }],
    "startedAt": "2026-11-08T01:20:00.000Z"
  },
  "events": [
    { "seq": 13, "type": "applied", "updates": [{ "assetId": "a_3", "dimensionId": "d_1", "value": 350, "lastRev": 44 }], "revision": 44 }
  ]
}
```

- 没有任务时返回 `{ "job": null, "events": [] }`。
- 客户端把 `seq` 作为下一次 `since`；刷新后从 0 开始也可，事件幂等。
- `items` 可只返回非 pending 的项，减小体积；`inFlight` 必须完整。
- 轮询间隔 800ms；页面不可见时暂停；回到可见立即拉一次。

#### 停止任务

```http
POST /api/preview-pages/ai-dimensions/stop
{ "jobId": "job_..." }
```

响应 `{ "ok": true }`；服务端清空队列、abort 正在处理的请求、状态改 `stopped`；已应用保留。

### 7.4 条件写库（“最新编辑优先”）

任务开始时逐坐标记录 `last_rev`（快照）。每张图成功返回后：

```sql
UPDATE preview_dimension_values
SET value = ?, last_rev = ?
WHERE page_id = ? AND asset_id = ? AND dimension_id = ? AND last_rev = ?;
```

- `changes = 0` → 任务开始后被改过 → 跳过该坐标，记 `skipped`。
- 每张图一个事务；成功写入至少一个坐标才 bump 一次 `preview_pages.revision`。
- 新 `last_rev` = 本次 bump 后的 revision。
- 单张图多个维度：要么全在同一个事务里，要么逐条条件更新、逐条记录；不要因为一条 `changes=0` 回滚其他条。
- 维度被删：`UPDATE` 影响 0 行；跳过。
- 素材被移出 Page：跳过。

> 现有 `last_rev` 是“该坐标最后一次写入时的 Page revision”，由 `PATCH /api/preview-values` 维护（`preview-pages.js:239-245`）。本功能复用，不新增列。

### 7.5 逐图 loading 与锁定（客户端）

- 客户端从 `job.inFlight` 得到 `lockedAssetIds`。
- `DimensionPreview`：
  - 对 `lockedAssetIds` 中的图片渲染遮罩 + `Spinner`；
  - 禁用这些图片的拖动（1D/2D）与平面卡片拖动；
  - 详情抽屉里这些图片的维度滑块禁用，显示“AI 处理中”；
  - 其他图片、维度名称、增删维度、缩放/平移/隔离/模糊/专注模式不受影响。
- 防御：`onUpdateAssetDimensions` 在 App 层再检查一次锁定集合，锁定的坐标直接忽略。
- 堆/平面：
  - 收起堆中若有锁定图，堆右上角显示小 spinner；
  - 展开平面中对应卡片显示遮罩；
  - 堆整体本来不可拖动，不需要额外处理。
- 3D：只显示遮罩；3D 本来不允许拖图。
- 超时/应用后 `inFlight` 移除，遮罩与锁定立即消失。

### 7.6 超时与迟到结果

- 服务端每次模型请求包一层超时（默认 60 秒）。
- 超时：
  - 记录 item `timed_out`；
  - abort 请求；
  - 从 `inFlight` 移除；
  - 不写库。
- 如果底层请求在 abort 后仍返回（或实现选择不 abort）：
  - 写库前检查 item 状态/`timed_out` 标记与 deadline；
  - 已超时则直接丢弃，绝不补写。
- 超时不终止整个任务；继续下一张。
- 客户端只看到该图解锁 + 胶囊超时计数 + 最终汇总，不逐张弹窗。

### 7.7 后台运行、刷新与切页

- 任务不绑定 HTTP 连接，创建后立即返回；服务端自己跑。
- 客户端轮询是“读状态”，断开不影响任务。
- 刷新：
  - 新页面先 `GET /api/preview-page` 拿到已应用的值；
  - 再 `GET job` 拿 `status/inFlight/events`；
  - 恢复胶囊与锁定。
- 切 Page/项目/自由画板：
  - 停止轮询（不再需要）；
  - 任务继续；
  - 回到所属 Page 时再拉 `GET job`。
- 服务重启：
  - 内存任务丢失；
  - 轮询 404 或 `job:null`；
  - 客户端提示“AI 标注已中断，已应用的维度保留”；
  - 不自动恢复。
- 用户登出/会话过期：任务已在服务端创建，继续跑完；后续轮询 401 时客户端停止显示。

### 7.8 停止

- 胶囊停止按钮 → `POST stop`。
- 服务端：
  - `cancelRequested = true`；
  - 清空 `queue`；
  - abort 所有 `inFlight` 请求；
  - 状态 `stopped`，记录 `finishedAt`；
  - 已应用结果保留。
- 客户端：
  - 立即清空 loading/锁定；
  - 胶囊消失；
  - toast 汇总。
- 停止不可撤销；要重新标注就再跑一次。

### 7.9 并发与限流

- **单任务内**：默认 **2 张图在飞**（Q11），可降到 1。无论几路，**一次模型请求只含一张图**。
- **全局**：同一时间只允许 1 个 AI 维度任务（R14）；不同 Page 也返回 409。
- 429/5xx：同一张图退避重试 1 次；仍失败记该图失败。
- 不建议超过 2 路：同一个 AI key 的 RPM/TPM 很容易被打满，且同时处理太多张会让用户看不清“正在处理哪张”。

### 7.10 权限

- 未登录：401。
- 游客：403；按钮不显示。
- 成员/管理员：可用；AI 配置由管理员预先保存，成员不需要配置权限。
- 同一 Page 的其他登录成员能看到任务进度与逐图 loading，但默认只有任务创建者和管理员可以停止；`canStop` 由服务端计算。
- AI 配置仍仅管理员可读写（现有 `/api/ai-config` 规则）。
- 未配置 AI：点击开始时返回 400，toast 提示管理员配置；本轮不新增成员可见的配置状态接口。

### 11.2 补充说明（已确认）

- **Q11 任务内并发**：每张图片始终是独立的一次模型请求；并发 2 表示同时有两张图在请求模型、两个 loading、两张图各自锁定；完成顺序可能不同。并发越高越快，但更容易撞 AI 限流，也更难看清进度。本方案取 **2**。
- **Q13 任务状态**：任务状态指“队列、进度、哪张图正在处理、已产生的事件”。只放服务端内存时，刷新页面、切 Page、关标签页都不影响任务，只要 Node 进程没重启；服务一重启，任务中断，但已经写进 `preview_dimension_values` 的值还在。本方案**不落库**。
- Q12（单图超时 60 秒）与 Q14（全局只跑 1 个批量任务）已确认，不再列为待确认。

### 12.2 S1：服务端契约骨架（单图接口 + 批量任务占位）

**目标**：先把“单图同步标记 / 批量任务创建 / 查询 / 停止”的契约固定下来。此阶段**不调用 AI、不写维度值**：单图接口返回空结果，批量任务用占位处理器把每张图标记为 `skipped`，专门验证路由、权限、参数校验和状态机。

**步骤**

1. 新建 `app/server/preview-ai.js`：

   - 导出 `handlePreviewAi(request, ctx)`。
2. 在 `preview-ai.js` 实现：
   - `POST /api/preview-pages/ai-dimensions/single`：校验 `projectId/pageId/assetId`、素材属于 Page 且是图片、维度归属、`dimensionIds`（省略=全部，最多 20）、`mode`（`zero`/`all`，默认 `zero`）、AI 配置存在、同 Page 没有单图/批量任务；返回 `{ ok:true, updates:[], skipped:[], revision }` 占位，不调 AI、不写库。
   - `POST /api/preview-pages/ai-dimensions`：校验 `projectId/pageId`、Page 归属、维度归属、`dimensionIds`（省略=全部，最多 20）、`mode`（`zero`/`all`，默认 `zero`）、图片数/目标图片数（≤200）、AI 配置存在、全局无活动任务；创建 `job`，返回 `202 { jobId, total }`。
   - `GET /api/preview-pages/ai-dimensions/job?projectId&pageId&since=`：返回 `{ job: null | {...}, events: [...] }`；`job` 含 `status/total/done/applied/skipped/failed/timedOut/inFlight/items/canStop`。
   - `POST /api/preview-pages/ai-dimensions/stop`：校验 `jobId`，设置 `cancelRequested`，清空队列，状态 `stopping`，返回 `{ok:true}`。
3. 本阶段的任务处理器先用占位：按队列逐个延迟约 50ms 后把 item 标为 `skipped`、`done++`，然后 `done` 结束；**不调用 `ai.js`，不写 `preview_dimension_values`**。延迟是为了让测试能观察到 `running`。
4. 在 `app/server/routes.js` 引入并挂载：
   ```js
   import { handlePreviewAi } from "./preview-ai.js";
   ...
   // 放在游客拦截之后、handlePreviewPages 之前
   if (pathname.startsWith("/api/preview-pages/ai-dimensions")) {
     if (user.role === "guest") return Response.json({ error: "游客只能浏览，不能进行此操作" }, { status: 403 });
     return await handlePreviewAi(request, ctx);
   }
   ```
   - 注意不要把它加进 `["/api/preview-pages", ...].includes(pathname)` 那个精确匹配数组。
5. 在 `app/test/api-smoke.mjs` 加契约用例（不需要 AI mock）：

### 12.9 C4：后台恢复、多用户与权限

**目标**：让“刷新、切页、关标签页不打断”真正可用；同一 Page 的其他用户能看到进度，但不能随便停。

**步骤**

1. `useAiDimensionTag` 的 adopt：
   - 挂载/切 Page 时 `GET job`；`status=running/stopping` → adopt，用 `since=0` 重放已应用事件（幂等，不会漏掉页面加载后到 adopt 之间的结果）；
   - `status=done/stopped/error` → 只更新状态，不显示胶囊；
   - `job=null` → idle。
2. 轮询生命周期：
   - 页面隐藏时暂停；`visibilitychange` 可见时立即拉一次；
   - 卸载只清定时器，不调 stop；
   - 401 时走现有 `notifyUnauthorized()`，停止轮询。
3. 多用户：
   - `GET job` 返回 `canStop`；非创建者/非管理员只显示进度，不显示停止；
   - 同一 Page 的另一用户也能看到 `inFlight` 锁定（他们的轮询拿到同一 job）。
4. 服务重启：
   - `GET job` 返回 `job:null` 或 404；客户端提示“AI 标注已中断，已应用的维度保留”，清理状态。
5. 权限：
   - 游客不显示按钮；直接调接口 403；
   - 成员可创建；AI 配置仍管理员。

**验收**

- [ ] 手工 5：处理中刷新；胶囊恢复、进度恢复、任务继续。
- [ ] 手工 6：切自由画板再回来；任务继续；自由画板看不到 AI 胶囊。

- [ ] 同一 Page 第二个用户：能看到进度；非创建者没有停止按钮。
- [ ] 服务重启模拟：任务中断提示；已应用值保留。
- [ ] 游客/未登录/401：正确 403/401/跳登录。

**退出条件**：后台语义完整，多用户不互相破坏。

## 13. 风险与取舍

1. **2 张并发的耗时**：200 张图 × 每张 8～15 秒，2 路并发仍可能 15～25 分钟；确认框给出预计时间；可停止；不建议再调高并发。
2. **后台任务的可见性**：用户切走后只能在回到所属 Page 时看到进度；不会跨 tab 显示。这是按“胶囊只属于维度预览”的要求做的。
3. **服务重启丢任务**：内存任务丢失；已写入的保留。Q13 已确认本轮不落库；若以后需要跨重启恢复，再单独立项。
4. **`all` 模式覆盖风险**：会覆盖任务开始前的已有值；确认框必须明确警告。`zero` 模式是安全默认。
5. **逐图锁定的范围**：已确认只锁正在处理的 1～2 张图，不冻结整页；其他图仍可编辑。
6. **并发编辑**：条件写依赖 `last_rev`；任何绕过 `/api/preview-values` 直接写表的代码都会破坏保护。
7. **维度改名/删除**：每张图发送时取最新名称；请求发出后改名，该维度结果跳过。已应用的值不回滚。
8. **超时判定**：60 秒是经验值；网络慢/图片大时可能误杀。可配置，先按 60 秒。
9. **模型准确率**：维度两端名称越抽象，结果越不稳定；用户可随时改，AI 不覆盖用户改过的坐标。
10. **无撤销**：误点一次会改很多值；`zero` 默认 + 确认框 + 停止按钮是缓解手段，不是撤销。
11. **全局单任务**：一个批量任务跑着时，其他 Page 不能开始批量；对小团队可接受，对多人同时使用可能要改成“每 Page 一个任务 + 全局并发 2”。
12. **AI 服务不可用**：现有单图 AI 打标也会遇到；本功能放大影响面，错误提示要明确。

## 14. 术语

| 术语 | 含义 |
| --- | --- |
| 维度 Page | 项目下的独立维度画板，拥有自己的素材集合、维度定义和坐标值 |
| 坐标 | 一个 `(page_id, asset_id, dimension_id)` 的值，界面范围 -100～100，存储 0～1000 |
| 0 / 中点 | 界面值 0，存储值 500；`zero` 模式把它视为“未修改过” |
| `last_rev` | 该坐标最后一次写入时的 Page revision；本功能用作“任务开始后有没有人改过”的判断依据 |
| 条件写 | `UPDATE ... WHERE last_rev = 快照值`；改过就不写 |
| inFlight | 正在请求模型、尚未返回的图片集合；客户端据此显示 loading 并锁定 |
| 胶囊 | 左下角的任务状态提示，含进度与停止按钮 |
| 后台任务 | 不依赖浏览器连接、在服务端继续跑的任务 |
